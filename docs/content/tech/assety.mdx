## Jak to funguje

### Dvě složky s assety

| Složka | Obsah | Jak se načítá |
|---|---|---|
| `assets/` (kořen repa, sdílená s Java verzí) | `textures/`, `audio/`, `fonts/` (+ Java `shaders/`, `discord-api/`) | **za běhu** z disku |
| `rust/assets/` | `rooms/*.json` (23 šablon místností), `tilesets/dungeon.json`, `tilesets/dungeon_wide.json` | **při kompilaci** přes `include_str!` |

Šablony místností a tilesety jsou tedy zakompilované do binárky; změna JSON vyžaduje rebuild.

### Hledání kořene assetů (`storage::assets_root`)

1. Proměnná prostředí `BANE_ASSETS`, pokud je nastavená.
2. Jinak se od složky spustitelného souboru jde nahoru a hledá první `assets/` nebo `Resources/assets/` (macOS bundle), která obsahuje `textures/`. Při `cargo run` z `rust/` to najde kořenové `assets/`.
3. Když nic, chyba v logu a fallback na `./assets`.

### Načítání (`Loader` v `assets.rs`)

Načítání je rozdělené na kroky — jeden krok za průchod smyčkou, takže loading screen se animuje:

1. Hned při startu (synchronně): `EARLY_TEXTURES` = logo, titulek loadingu, spinner (samostatné GPU textury).
2. Fronta kroků: každá textura z `GAME_TEXTURES` se dekóduje do paměti → „holed“ textury ukazatelů → **jeden krok `Atlas`** nahraje vše najednou do atlasu → každý zvuk (`Audio::files()`) se přednačte → font v každé `FontSize`.
3. Po posledním kroku `assets.mark_loaded()`; scéna Loading pak přepne do menu.

Textury se adresují **typovanými klíči** `Tex` z makra `texture_keys!` (modul `assets::tex`), např. `tex::PLAYER`, `tex::GUNS_RAILGUN`. Překlep = chyba kompilace. Chybějící (nenačtená) textura se vykreslí jako bílý quad a zaloguje varování.

## Interakce

- Šablony místností (`rust/assets/rooms`) a tilesety: [Dungeon](/docs/dungeon).
- Rozvržení sheetů a vrstvy: [Rendering](/docs/tech/rendering).

## Kde v kódu

- `assets.rs` → `Tex`, `tex::*`, `EARLY_TEXTURES`, `GAME_TEXTURES`, `Textures::get`, `Assets`, `Loader`
- `storage.rs` → `assets_root`, `BANE_ASSETS`, `ASSET_DIRS`
- `render/texture.rs` → `Pixels::load`, `load_with_hole`
- `dungeon/template.rs` — `include_str!` šablon místností
- `tilemap/tileset.rs` — `include_str!` tilesetů

## Jak přidat novou texturu

1. Ulož soubor do `assets/textures/ingame/…` (`.tga` nebo `.png`; sprite sheet = mřížka stejně velkých buněk).
2. V `assets.rs` přidej do `texture_keys!` řádek `NOVA = "ingame/nova.tga",`.
3. Přidej `tex::NOVA` do `GAME_TEXTURES` (jinak test `every_texture_key_is_loaded_by_one_of_the_lists` selže).
4. Použij `textures.get(tex::NOVA)` v prefabu.
5. `cargo test` ověří existenci, dekódování a vejití do atlasu.

**Nová šablona místnosti:** JSON do `rust/assets/rooms/`, řádek `include_str!` v `dungeon/template.rs` (podrobnosti v [Dungeonu](/docs/dungeon)).

## Nápady / chybí

- Assety jsou rozdělené mezi `assets/` (sdílené s Javou) a `rust/assets/`; až Java zmizí, stálo by za to je sjednotit pod `rust/assets/`.
- `assets/shaders/` (32 GLSL) a `assets/discord-api/` jsou pozůstatky Java verze, Rust je nečte.
- Seznam `GAME_TEXTURES` je ruční duplikát klíčů z `texture_keys!` — makro by mohlo generovat i seznam načítání (výjimkou jsou jen `EARLY_TEXTURES`).
- Žádný hot-reload; šablony místností vyžadují rebuild, textury restart.
- `.aseprite` zdroje leží jen u 8 textur; ostatní vznikají Python generátory — chybí dokumentace, který asset vzniká kterým skriptem.
