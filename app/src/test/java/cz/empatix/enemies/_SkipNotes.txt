Partial coverage / deliberately NOT asserted (with reasons):

- SpitCobweb projectile-emission path (update() -> canShoot -> fixedUpdate spawns a CobwebProjectile)
  is NOT driven to the spawn point. It is gated on Animation.hasPlayedOnce(), and Animation.update()
  only advances when real wall-clock time exceeds the per-frame delay (private lastAnimation /
  playedOnce fields live in the separate game-engine-render module and are not safely reflectable).
  Forcing it would require Thread.sleep (disallowed). We assert the pre-spawn invariant instead.

- SpiderlingTeleport is NOT unit-tested directly: its only public behaviour (activate/fixedUpdate)
  is gated on the same Animation.hasPlayedOnce() timing wall and on BehindTargetTargetting state; the
  teleport branch cannot be reached headlessly without sleeping or animation-frame reflection.
  BehindTargetTargetting (the substantive logic it delegates to) IS covered separately.

- Boss/enemy collectSubRenderables is only smoke-exercised when no damage popups are pending. After a
  hit, VitalityDisplayService holds VitalityChange entries whose collectSubRenderables calls
  Font.getDrawables on a mock Font (-> NPE). BossBaseEnemy additionally renders its boss-name
  CommonText the same way. These render-output paths are out of scope per the headless rules.

- renderData()/canRender() that build OutlineBinding/SpawnBinding or rotate laser vertices are not
  asserted: they exercise GL-adjacent render plumbing, not domain logic.

- service/ package (EnemyService, EnemyFactory, EnemyBoundsService, EnemyDropService,
  VitalityDisplayService) was outside the requested target set (domain, domain.bosses, skills).
