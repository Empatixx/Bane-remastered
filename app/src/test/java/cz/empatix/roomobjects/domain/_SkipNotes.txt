Skipped roomobjects.domain classes and why
=========================================

Scientist
  Constructor does `new PlayerUpgradeService()`, which:
    - builds three full UpgradeTrees via UpgradeTreeFactory (each tree constructs many
      HUD/menu sub-elements that fetch GPU textures/fonts), and
    - constructs a FileUpgradeService and calls `fileUpgradeService.load()` in the ctor,
      i.e. it reads the persisted-upgrades file from disk.
  This couples Scientist construction to real file IO plus a deep, GL-heavy menu graph that
  is well outside the headless asset-stub seam. The interaction handler also drives the
  upgrade menu (font.getDrawables) which NPEs with a mocked Font. Not constructible/usable
  headlessly with the available seams -> skipped. (PlayerUpgradeService itself deserves its
  own targeted suite with a stubbed FileUpgradeService, separate from this domain package.)

Partial coverage notes
-----------------------
Chest
  The open transition is fired by a dyn4j PLAYER collision callback registered on a PRIVATE
  physics body that the class does not expose. There is no headless seam to deliver that
  collision, so only the closed-state invariants (not removable, no drops while closed,
  geometry, position) are asserted. The open/drop/push-by-player path is not reachable here.

Time-gated animation flags (BarrelExplosion.hasPlayedOnce, Flamethrower active frame, etc.)
  Animation frame advance is gated on System.currentTimeMillis() deltas. Per the no-Thread.sleep
  / determinism rule, tests drive the update() paths (proving they run cleanly) but do not assert
  on the exact frame the wall clock lands on. Damage/state flags that are set synchronously
  (health, isDead, drop-once guard, trap type, coin spend) ARE asserted directly.
