ProceduralMapGenerator — SKIPPED (cannot be exercised headlessly).

The only public entry point is generate(...), which is not splittable from its GL/asset-coupled
tail:
  - generatePaths(...).forEach(constructRoom) and transform(...) both call RoomGenInfo.constructRoom(),
    which instantiates concrete Room implementations (StartRoom, CommonRoom, BossRoom, ...). Those
    build real TileMap / tile geometry that uploads to OpenGL (GLInit / GPU buffers) and pulls in
    asset textures. There is no seam to substitute a fake Room factory — constructRoom() is a method
    on each RoomGenInfo subclass with no injection point.
  - generate() then calls Room::init on every produced room, again touching GL state.

The private placement/graph algorithms (setNeighboursForRooms, generatePaths, setOrientationAround,
transform) are not reachable without running the full generate() pipeline and are not exposed.

The deterministic structural invariants requested (room count range, start/boss presence,
connectivity, non-overlap) all depend on the constructed Room graph, which is unavailable headlessly.

Covered elsewhere instead: the per-room geometry / neighbour / intersection logic that the generator
relies on is exercised directly in map/domain/RoomGenInfoTest (initDimensions, intersects,
addNeighbour / available directions, canCreateNeighbours, room-type mapping, setOrientationAround
non-throwing placement). RoomDirection.getOpposite and related helpers are covered in
map/domain/RoomDirectionTest.
