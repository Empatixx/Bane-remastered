SettingsMenuService — SKIPPED (cannot be constructed headlessly).

Reasons:
1. The constructor calls SettingsService.getInstance().getResolutions(), which delegates to
   WindowHandler.getMonitorResolutions(). WindowHandler statically references GLFWInit.window and
   makes live GLFW calls (glfwGetVideoModes / monitor enumeration). With no GLFW context this throws
   / returns no usable monitor list, and there is no seam to stub it (static, no DI, no MockedAssets
   equivalent for GLFW).
2. The constructor wires a large tree of GL/asset-coupled UI widgets (CommonBackground,
   StickyHoverButton, Slider, Checkbox, CommonButton, SlidingListText, UISelector). Several of these
   compute layout via Font.getWidth/getHeight and image atlas math; while AssetsService can be
   mocked, the GLFW monitor dependency above is the hard blocker.

SettingsService itself is also not unit-testable in isolation here: it is an eager singleton
(private static final INSTANCE = new SettingsService()) whose construction reads settings.json from
disk and builds a SettingsApplier (audio/GL). Its setters merely mutate an unapplied GameSettings;
the pure value-holder behaviour is already covered by GameSettingsTest in settings/domain.

Covered elsewhere instead: settings/domain/GameSettingsTest (value semantics / deep copy).
