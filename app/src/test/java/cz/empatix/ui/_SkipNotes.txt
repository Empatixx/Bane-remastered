UI package test coverage — skip / partial-coverage notes
========================================================

All concrete classes in cz.empatix.ui are covered by tests in this package. A few
classes/methods are only PARTIALLY exercised; the reasons are recorded here.

Interfaces (no implementation to test directly — covered via implementors):
- UIElement      : interface; covered through CommonButton, Checkbox, Slider, etc.
- SelectableUI   : interface; covered through StickyHoverButton and UISelector mocks.

Partial coverage / deliberately untested paths:

- Slider.update(...) drag path:
    SKIPPED (the selected==true branch). The GL-free fake atlas entry from MockedAssets is
    16x16, and the slider's cursor (StickyHoverButton 16x16 @ scale 2 -> width 32) ends up exactly
    as wide as the scaled track (also 32). The drag math divides by
    (dimensions.x() - cursor.getWidth()) == 0, yielding NaN/Infinity. This is a fixture-geometry
    artifact, not real behaviour, so the drag-to-value path is not asserted. setValue(...) (pure
    multiplication, no division), positioning, geometry getters, and the release/un-select
    transition ARE covered. The off-cursor mousePressed path (selected stays false) is covered so
    update() runs safely.

- Any method that ultimately calls CommonText.collectSubRenderables(...) -> Font.getDrawables(...):
    AVOIDED everywhere. The mocked Font returns null from getDrawables, causing an NPE that reflects
    the GL stub, not production behaviour. We therefore do not call collectSubRenderables/renderData
    paths that build font drawables. Font.getWidth/getHeight return primitive 0f under the mock and
    are safe, so centring/positioning math is exercised.

- SlidingListText.renderData()/getZIndex()/canRender():
    Asserted to throw IllegalStateException (their documented "not implemented" contract) rather
    than producing render output.
