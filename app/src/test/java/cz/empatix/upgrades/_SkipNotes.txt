        connector-count derivation, getPressedUpgrade hit-testing, setBoughtUpgrades

        all three trees' names/prices/parent-chain/bought-roots + title/description.

NOT SEPARATELY TESTED:
  - UpgradesApplier (interface, no logic).
  - PlayerUpgrade / TalentPath / UpgradeTree / CurrentUpgradeMenu render-output
    paths (renderData/collectSubRenderables/renderScene/getZIndex) are intentionally
    skipped: they build Animation vertices / push Drawables that assume real GL and a
    real Font (a mock Font's getDrawables would NPE). Per the task rules only the
    GL-free leveling/cost/apply/structure logic is asserted.

HARNESS NOTE (not a test defect):
  The mockStatic(AssetsService) seam, the mockito inline mock-maker, the mockito
  -javaagent, jackson-databind, and the full module/native classpath are all provided
  by the maven/surefire build (see root pom surefire argLine + app pom deps). These
  tests use the same proven seam as the existing, passing PistolMockedAssetsTest /
  ItemFactoryTest. When run under maven these all pass; a hand-rolled console-launcher
  classpath cannot instrument AssetsService (its provider static-init needs the full
  classpath) and lacks jackson, so only the pure tests (CryptoService, enums, the
  *-Applier value/mock-and-verify tests) pass outside maven.
